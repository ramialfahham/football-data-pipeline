# Verification — repaired player names and the exported-text check

Read on the committed sample build of `site_v2` (`npm run build`, 2,272 pages), 2026-11-06.

criteria_demonstrated:
  - Every player name on the site shows its own letters: the built pages carry "A. Maksimović" on 6 pages, "M. Ljubičić" on 6, "K. Urbański" on 3, "L. Jovanović" on 3 and "M. Cvetković" on 3. "J. Potočnik", "A. Voitinovičius" and "N. Kovač", garbled on main, now stand correct in the committed data (`teams/192.json`, `teams/211.json`, `teams/867.json`); no built page of the sample shows those three. `check-font-coverage.mjs` reports 0 characters missing on 0 pages, where main held U+0084, U+0087 and U+008D. In prod, the repair is proven in BigQuery by `assert_garbled_text_repair`: 0 failing rows on 24 fixed examples, all eight names among them.
  - A check fails the build when exported data holds text decoded in the wrong character set: `check-exported-text.mjs` runs in `prebuild` (`build-wiring.test.mjs` pins it) and reads 639 files with no finding. Its node test runs the command on a folder holding "J. Poto" + U+00C4 + U+008D + "nik": exit 1, and exit 0 on the correct spelling. The Latin-1 form, the Windows-1252 form, a three-byte sequence, a stray control character and the replacement character each fail; correct carons, a no-break space, German quotes, Finnish letters and Vietnamese letters each pass.
