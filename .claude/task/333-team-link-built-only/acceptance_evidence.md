# Verification — a team row links only to a team page the build makes

Instrument: `npm run build` in site_v2 on the committed sample plus the live export of 21 Nov (88,230 files): its `competitions/WCQAF/2023.json` and the 53 team payloads of its standings teams copied into `src/data`, which is the Africa qualification page with Eritrea (no `teams/` file in the live export, 3,391 files) among 54 standings rows. 2,535 pages built; the built `dist/{en,de,fi}/world-cup-qualification-africa/index.html` was read, not the source. `node --test src/lib/builtTeams.test.mjs`: 2 passed.

criteria_demonstrated:
  - **A team row on any page leads to the team page when this build makes one, and is plain text when it does not:** in the built `/en/world-cup-qualification-africa/` 52 of the 53 standings rows read `<a href="/en/teams/<slug>/" class="ctab-row">` (for example `/en/teams/egypt/`, `/en/teams/burkina-faso/`), each with its team payload in `src/data/teams`; the one row of a team with no payload is `<div class="ctab-row">`. The same counts hold in DE (`/de/mannschaften/…`) and FI (`/fi/joukkueet/…`).
  - **The World Cup qualification Africa page (EN, DE, FI) has no dead internal link: Eritrea's row in the standings is plain text:** in the built page of each locale the row named Eritrea is a `div` (`<span class="nm">Eritrea</span>`, rank 6, played 0), and the string `/en/teams/eritrea/` (`/de/mannschaften/eritrea/`, `/fi/joukkueet/eritrea/`) does not occur in the file. `node scripts/audit-seo.mjs` after the build reports no dead internal link; its 12 violations are the nation-page h1 rows of #296 (`/en/teams/morocco/` and 3 more nations, 3 locales).
  - **The Teams page and every table row take "the team has a built page" from one place:** `TableRow.astro` and `pages/[lang]/[teams]/index.astro` both call `hasTeamPage` from `site_v2/src/lib/builtTeams.mjs`, and the Teams page no longer reads `src/data/teams` itself (`grep -n "readdirSync" "site_v2/src/pages/[lang]/[teams]/index.astro"` returns no match). Two other readers stay as they were and are not table rows: the team route `[team].astro`, which emits the pages, and `playerPage.ts` `teamHasPage`, a player header's club link by team id.
