**No mock carries CSS of its own beyond its harness** (the toggles, the stage, the legend). Every
element's CSS is `site_v2/src/styles/system.css`, inlined verbatim; the element, its rule and
its measurements are `docs/wireframes/block_standard.md` (the block standard). Two scripts hold
it: `scripts/check_page_css.py` fails a generator (or a module it imports) whose CSS string
touches an inventory class, and `scripts/check_design_inventory.py` renders every generator the
block standard lists at 375px and 700px in EN and FI — the only two languages a mock carries; a
built page is rendered in every locale the site publishes — and measures every element. A page-level
class that happens to share a name with an element's is renamed, not argued about.

**Proposed seed shapes** live beside the generators and are read by them, because `!27` needs a
clean tree: `competition_types.proposed.csv` (the shipped seed + `scope`, `label_i18n_key`,
`label_en`) and `confederations.proposed.csv` (new, 7 rows). Both are guarded against the shipped
seed and against the registry's own documented enum, so a mock cannot be designed against a
taxonomy that is not real.

## Provenance is the contract (#58)

Every element on a page design declares its source; **a value with no source is a named gap, never
a typed value**. `gen_competitions.py` carries the table (`PROVENANCE`) and renders it under the
mock, so the design and its provenance are one artifact.

Then the checks — each asserts the rules the design actually depends on, not just that a file was

```
python check_home.py

```

## Why the checks exist in this shape

Several were written after a defect got past the earlier ones:

- **`prove_check_fails.py`** exists because a check that has only ever been seen green proves
  nothing. It reconstructs the CSS that shipped the "Bayern MünchenBundesliga" bug and asserts the
  check fails on it.
- The container-query check selects the query **by content**, because the first `@container` in the
  file is the value-column one — `re.search` matched the wrong block.
- Label lookups key on **`(metric_id, entity)`**. Several ids carry both a team and a player row, so
  keying on `metric_id` alone silently takes the wrong label; that is the exact bug `!27` fixed in
  `export_metric_definitions_json.py`.
- Sort order is checked against each metric's catalogue **`direction`**, so a lower-is-better metric
  cannot be ranked descending without an explicit recorded ruling.

## Not design tooling, but kept because they were expensive

- `make_payload.py` — builds a JSON body for `glab api --input`. `--raw-field description=@file`
  silently sends the *path*, not the file.
- `scan_issue.py` — scans a fetched issue for stale terms, forcing UTF-8 both ways.
- `check_handover.py` — size against the 16,000-character cap, NEXT numbering, duplicate lines, and
  presence of key phrases **whitespace-collapsed** (a line-based match misses a phrase that wraps).
- `section_sizes.py` — per-section character counts, for deciding what to trim.

`gen_home_with_rules.py`. They were written in a session scratchpad during the review and

Two are overlays: they import the repo generator (`gen_competition_hub.py`, `gen_home.py`) and

side effect of the import.

### A render sent for review is a file of record — `renders/<page>_<YYYY-MM-DD>_<nn>.html`

**A render sent for review is never overwritten** (#153). It lives in `design-mocks/renders/`,
**tracked** (the ignore rule above stops at this folder's own `*.html`), under a name nobody
picks by hand: the page, the date, and a two-digit number that counts up per page across dates
and never resets. `render.py` picks the name and runs the generator with it as its one argument:

```
python design-mocks/render.py gen_overview_after_teams.py  competition-overview
python design-mocks/render.py gen_competition_matchdays.py competition-matchdays
python design-mocks/render.py gen_competition_teams.py     competition-rankings
python design-mocks/render.py gen_home_with_rules.py       home
```

It refuses to write over an existing file, and `tests/test_design_mock_renders.py` fails on a
name outside the pattern, a gap in a page's numbering, a later number with an earlier date, or a
render an ignore rule would swallow. A render made to look at and not sent is deleted, not renamed.
A generator run by hand with its own output name (as before) writes a working file, not a record.

The four renders the CPO approved on #129 are `renders/competition-overview_2026-09-16_01.html`,
`competition-matchdays_2026-09-16_01.html`, `competition-rankings_2026-09-16_01.html` and
`home_2026-09-16_01.html`. Re-running the generators reproduces the Matchdays and Rankings renders
byte for byte; the Overview and Home renders differ only in a `<title>` and a CSS comment that
carried a date (code comments carry no dates here).
