```
python check_home.py

```

## Why the checks exist in this shape

Several were written after a defect got past the earlier ones:

- **`prove_check_fails.py`** exists because a check that has only ever been seen green proves
  nothing. It reconstructs the CSS that shipped the "Bayern MünchenBundesliga" bug and asserts the
  check fails on it.
- The container-query check selects the query **by content**, because the first `@container` in the
  file is the value-column one — `re.search` matched the wrong block.
- Label lookups key on **`(metric_id, entity)`**. Several ids carry both a team and a player row, so
  keying on `metric_id` alone silently takes the wrong label; that is the exact bug `!27` fixed in
  `export_metric_definitions_json.py`.
- Sort order is checked against each metric's catalogue **`direction`**, so a lower-is-better metric
  cannot be ranked descending without an explicit recorded ruling.

## Not design tooling, but kept because they were expensive

- `make_payload.py` — builds a JSON body for `glab api --input`. `--raw-field description=@file`
  silently sends the *path*, not the file.
- `scan_issue.py` — scans a fetched issue for stale terms, forcing UTF-8 both ways.
- `check_handover.py` — size against the 16,000-character cap, NEXT numbering, duplicate lines, and
  presence of key phrases **whitespace-collapsed** (a line-based match misses a phrase that wraps).
- `section_sizes.py` — per-section character counts, for deciding what to trim.

## Every number in the mocks is placeholder

The player and team names are real; the values attached to them are invented and were never
measured. Nothing here has been run against BigQuery.
