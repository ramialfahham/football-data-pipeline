# WC 2026 — Competition brief

This document records WC-specific product/data behavior for the current pipeline implementation.

## Registry and identifiers

- Internal league code: `WC` (not `WC26`)
- API league id: `1`
- WC qualifiers (WCQ* league codes) are first-class competitions linked to WC via `parent_competition: "WC"` in `docs/competition_registry.yml`. Team form is recency-based (cross-competition last-N finished matches, `int_form_window__team`), so no explicit qualifier mapping is needed. The old `wc_supporting_league_codes` seed was retired; a Core parent-child dim is reserved for GAP-18.

## Match preview flow

WC follows the same app flow as domestic competitions:

`landing -> fixture-list -> match-preview`

There is no separate pre-tournament page in the Pages app.

## WC form window rules

For `mart_matchday_insights_wc`:

1. Group Stage Matchday 1 fixtures use qualifier form:
   - all finished matches for each team across configured WC supporting qualifier leagues
2. Group Stage Matchday 2 onward (including knockout) use tournament form:
   - all finished `league_code = 'WC'` matches before the fixture kickoff
   - cumulative (no five-game cap)

If a metric is missing in source stats, numeric outputs remain `null` and UI renders `"-"`.

## Fixture eligibility for WC previews

Only confirmed upcoming WC fixtures are exported/rendered for previews:

- `status_short = 'NS'`
- both teams resolved (`home_team_sk` and `away_team_sk` present)

TBD/unresolved pairings are excluded from preview exports until teams are known.
