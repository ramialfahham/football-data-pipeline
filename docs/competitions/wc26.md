# WC 2026 — Competition brief

This document records WC-specific product/data behavior for the current pipeline implementation.

## Registry and identifiers

- Internal league code: `WC` (not `WC26`)
- API league id: `1`
- WC qualifiers (WCQ* league codes) are first-class competitions linked to WC via `parent_competition: "WC"` in `docs/competition_registry.yml`, now synced into the `competition_registry` seed. Team form follows the tournament window (GAP-18, `int_team_momentum_window`): qualifier matches before the team's first WC match, then cumulative WC matches once the tournament is under way — not last-5. The old `wc_supporting_league_codes` seed was retired and replaced by the registry parent link, which the window model reads directly (no separate Core dim).

## Match preview flow

WC follows the same app flow as domestic competitions:

`landing -> fixture-list -> match-preview`

There is no separate pre-tournament page in the Pages app.

## WC form window rules

Implemented generically by competition_type in `int_team_momentum_window` (GAP-18) and surfaced
on the shared momentum marts (the per-type `mart_matchday_insights_wc` was retired in #321):

1. Group Stage Matchday 1 fixtures use qualifier form (`window_type = 'qualifiers'`):
   - all finished matches for each team across its WC qualifier competitions
     (registry `parent_competition = 'WC'`)
2. Group Stage Matchday 2 onward (including knockout) use tournament form
   (`window_type = 'tournament_to_date'`):
   - all finished `league_code = 'WC'` matches this edition before the fixture kickoff
   - cumulative (no five-game cap)

If a metric is missing in source stats, numeric outputs remain `null` and UI renders `"-"`.

## Fixture eligibility for WC previews

Only confirmed upcoming WC fixtures are exported/rendered for previews:

- `status_short = 'NS'`
- both teams resolved (`home_team_sk` and `away_team_sk` present)

TBD/unresolved pairings are excluded from preview exports until teams are known.
