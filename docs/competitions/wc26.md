## Form source strategy

WC 2026 uses `form_source: all_internationals`. This means form is fetched per team via `/fixtures?team={id}&last=10` — the last 10 international fixtures across all competitions, not limited to a single league.

**Before the first WC match:** form comes from qualifier matches (the `supporting_leagues` entries in the registry).

**After the first WC match:** current tournament matches only. Qualifier data is dropped entirely.

This transition is implemented in `4_intermediate`. It is a feature decision scoped to WC26, not a general architecture pattern.

---

## History window

`history_seasons: 1` — current tournament year (2026) only. Qualifier data is accessed via the team-based fixture endpoint, not via historical season backfill.

---

## Ingestion approach

Form data uses `/fixtures?team={id}&last=10` per team — 48 API calls for the initial backfill. This is intentionally different from the league-based ingestion used for domestic competitions. The `form_data_strategy` field in the registry documents this.

---

## Known limitations at onboarding

- `statistics_fixtures` not yet active for the WC26 main tournament as of 2026-04-27. Monitor the coverage flags via `/leagues?id=1&season=2026`. Activate when available.
- OFC qualifier (league id 33) has no fixture statistics. Form for OFC-qualified teams will fall back to whatever international fixtures are available via the team endpoint.

---

## Staging model plan

WC26 will follow the same staging pattern as BL1: one `stg_apif__wc26_*` model per raw source table. Qualifier sources are ingested via the team-based form endpoint rather than as separate competition staging models (avoids 7 × 13 staging models for qualifiers that are only needed for form data).
